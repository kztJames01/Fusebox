01 / INPUTS / REACH

Many agents.
One execution gateway.

fusebox does not choose a model and does not talk to one. It sits between agents and tool processes, supervising execution and recording verifiable receipts.

01

AGENTS

Parallel work. Strict mediation.

Commands are mediated against declared intent policies. Unauthorized network or path escapes are blocked deterministically.

INTENT / BOUNDED
02

PLATFORMS

Terminal, MCP stdio, host hooks.

Connect Claude Code, Cursor, Copilot, or OpenCode over supervised MCP stdio, or run commands via the CLI.

CORE / SHARED
03

PROVIDERS

No model of its own.

Your tools can use any provider they already support. fusebox never calls them. Decisions come from local policy, not remote prompts.

API CALLS / ZERO

02 / RECORD / WORKFLOW

The execution becomes
the receipt.

No telemetry. No guessed intent. Supervised process boundaries produce tamper-evident cryptographic receipts.

  1. 01

    INPUT / COMMAND

    Agent declares intent.

    Tools or commands declare their scope. fusebox pre-resolves arguments before execution.

    intent → preflight
  2. 02

    SUPERVISION / MCP PROXY

    Supervised stdio relay.

    Sanitizes JSON-RPC traffic, isolates noise, drops secrets, and enforces backpressure.

    fusebox proxy -- <cmd>
  3. 03

    CONFINEMENT / OS BOUNDARY

    OS-level sandboxing.

    Filesystem and network restrictions contain the child process at the kernel level.

    landlock / seccomp
  4. 04

    RECEIPT / VERIFICATION

    Inspectable evidence.

    Append-only hash-chained ledger stores execution decisions and outcomes.

    fusebox why <receipt-id>

05 / GUARANTEES / INVARIANTS

Nothing leaves
the machine.

The constraints are the product. They make the record safe to store, cheap to query, and possible to trust.

  1. 01

    Zero outbound network.

    No telemetry, model API, or update check. Review and optional MCP HTTP are inbound on loopback.

    0 ↑
  2. 02

    Reference only.

    If a fact has no [file:line], it is not in the output. No reference, no memory.

    [ : ]
  3. 03

    Deterministic.

    Same tree, same ticket bytes. UI preferences live separately and never change a scan.

    A = A
  4. 04

    Hash-verified.

    State is written atomically. Exported cards carry a hash you can independently check.

    # OK
